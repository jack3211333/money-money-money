# 重要決定

| 日期 | 決定 | 原因 |
| --- | --- | --- |
| 2026-10-23 | 使用 Vite + React + TypeScript + PWA | 輕量、適合響應式網頁與安裝至手機主畫面。 |
| 2026-10-23 | 使用 Supabase Auth/Postgres + RLS | 提供雲端同步、Email 登入與依使用者隔離的資料安全。 |
| 2026-10-23 | 初期採 Email 魔法連結登入，後改為 Email＋密碼 | 初期降低登入流程複雜度；實機測試發現內建寄信額度會影響登入，因此改用密碼作為日常登入方式。 |
| 2026-10-23 | 使用 TWD 整數元儲存金額 | 避免浮點誤差，符合日常記帳。 |
| 2026-10-23 | 所有刪除採軟刪除 | 保留歷史資料並降低誤刪風險。 |
| 2026-10-23 | 不支援人際借貸 | MVP 僅管理金融負債：貸款與分期。 |
| 2026-10-23 | 使用 GitHub + Vercel 部署 | Git 推送後可自動部署，電腦關機也可使用。 |
| 2026-10-23 | PWA 使用原生 manifest + service worker | 套件版本在此環境發布內容不完整；原生標準可保有安裝與離線 app shell，且減少依賴。 |
| 2026-10-23 | 推演不建立真實交易 | 使用者可安全測試固定收支、負債與持續投入，不會影響帳本。 |
| 2026-10-23 | 股票以成本或最後手動市值修正作為估值基準 | MVP 不串即時報價，仍可用手動年化報酬率推演。 |
| 2026-10-23 | 改為 Email＋密碼登入，既有登入者可設定密碼 | Email OTP 與魔法連結共用 Supabase 內建寄信額度；密碼登入無須每次寄信，並可保留原帳號的 `user_id` 與資料。 |
| 2026-10-23 | PWA 頁面採網路優先快取，保留登入連結備援 | Vercel 更新後舊首頁可能引用失效的程式檔；既有無密碼帳號仍須一次登入才能設定密碼。 |
| 2026-10-23 | Vercel 網站是日常使用入口，本機開發伺服器可隨時關閉 | 雲端部署與 Supabase 資料庫獨立運作；電腦關機不會中斷正式網站。 |
| 2026-10-23 | 密碼設定必須在既有登入狀態下完成 | `updateUser({ password })` 需要目前的 Supabase session；設定後手機可直接用密碼登入，保留同一 `user_id`。 |
| 2026-10-23 | 先完成跨裝置驗收，再考慮自訂 SMTP | 自訂 SMTP 是改善信件額度與寄達率的部署工作，尚不阻擋密碼登入的核心流程。 |
| 2026-10-23 | 已完成密碼設定與手機登入驗收 | 確認同一 Supabase 使用者可在 Vercel 網站跨裝置登入；目前版本可作為 MVP 基準。 |
| 2026-10-23 | 分類採大小兩層，每個大分類最多 3 個小分類 | 保留日常記帳的結構感，同時避免分類過多難以選擇。 |
| 2026-10-23 | 預設收入 2 大類、支出 5 大類，並允許新增大小分類 | 提供開箱即用的常用分類，也保留個人化空間。 |
| 2026-10-23 | 大小分類均使用可自選的 Lucide 線條 icon | 以 55 個固定 key 的常用記帳 icon 提供跨裝置一致的外觀，且選項多於預設分類數量。 |
| 2026-10-24 | 帳戶圖標採獨立的四張靜態圖片與可為空的 `icon_key` | 與分類圖標區分；保留既有帳戶的未選擇狀態，並允許新增、編輯與清除圖標。 |
